# Contract decisions — integration reconciliation

One line per resolved CONTRACT-ISSUES item. "A§n" = CONTRACT-ISSUES-A item n.
All changes are additive; implementations were updated consistently.

- **Row binding (C§3, B§1):** `CBv2AttendingLayerCache.setRows(_:)` is now a contract requirement — the one canonical batch-binding method; `CBv2LayerCache`, `PagedLayerCache`, and all test mocks conform.
- **Windowed prefix adoption (C§1, A§3):** `CBv2SequenceKV.fastForward(to:)` added (default traps for full-attention). ONE semantics for both backends: the engine slices the matched prefix down by `cbv2RequiredRecompute` to a uniform `effective` offset; `makeSequenceState(adopting:)` positions every storage-owning row at that offset (full = snapshot write, windowed = fastForward), and the engine replays `[effective, prompt)` through ALL layers. WS-A's per-layer `matched - window` start was replaced (it breaks when windows differ), and the exactness note is: replayed windowed K/V is exact because K/V projections depend only on the layer's input (full-layer history is complete); only windowed-attention *outputs* at the first `window-1` replayed positions can deviate, which affects downstream layers of deeper hybrids but never the final-position logits of models whose windowed layers are last (TinyTestModel) — the accepted trailing-recompute policy of report 10 invariant 6.
- **Attention logit softcap (C§2):** construction-time layer-cache config on BOTH backends identically — `CBv2LayerCache(attentionSoftcap:)` (routes to the composed fp32 path, same as `PagedLayerCache(attentionSoftcap:)`). Verified against models: **Gemma 4 does NOT use attention-logit softcapping** (only `final_logit_softcapping`, applied in `applyLMHead`); the attention softcap exists for Gemma-2-family (`attn_logit_softcapping = 50.0`), so no Gemma 4 plumbing change was needed.
- **CBv2Engine Sendable (H):** adopted `CBv2Engine: AnyObject, Sendable`; `EngineV2` stays `@unchecked Sendable` with a written justification (lock + serial-queue confinement). WS-H can drop its box.
- **stepsExecuted (H):** `CBv2CapacitySnapshot.stepsExecuted` added (monotonic engine step count, default 0) and published by the loop after every step — direct wedge/liveness signal.
- **bytesReserved (C§4):** `CBv2KVBackend.bytesReserved` added with a default of `bytesInUse` (contiguous: reserved == in use); the paged backend reports its worst-case reservations so admission cannot over-admit.
- **Release fencing (B§4):** promoted into `CBv2KVBackend.release` contract text — the engine defers releases of state referenced by an in-flight step until finalization; backends may recycle storage immediately.
- **endAdoption (D§1):** `CBv2PrefixCache.endAdoption(tokens:matched:)` added to the protocol (default no-op); every `lookup` hit must be balanced by exactly one `endAdoption`.
- **requiredRecompute (D§3):** moved to the contract as the free function `cbv2RequiredRecompute(layerKinds:matched:)` (pure model-shape logic); `PrefixCacheV2` statics delegate to it.
- **Prefix-cache gate:** `CBv2SchedulerConfig.enablePrefixCache` (default false) added; EngineV2 additionally takes an optional `prefixCache:` instance — both must be set for prefix caching to be active.
- **Donation thread/materialization (D, C interplay):** `PrefixCacheV2.donate(tokens:snapshots:layerKinds:)` added — snapshots are built on the engine thread (graph-only, consistent with in-flight slab writes) and donated from the engine's donation queue; `CBv2PrefixCacheConfig.materializeOnDonate` (device eval, not a host readback) is REQUIRED for the paged backend whose donated views reference recyclable slab pages.
- **Sampler surface (B§2, E§2):** `CBv2StepSampler.sample` gained `pendingSampledTokens:` (lazy [B] of chained-decode in-flight tokens) and a lazy `rowContext:` provider of `CBv2SamplerRow` (id, params, prompt, confirmed output) — enough for `CBv2DefaultSampler` (LogitsPipelineV2 + SamplerV2) to reconfigure exactly on membership change with zero host syncs; `CBv2SamplerRow` is hereby blessed as the membership-change carrier type.
- **Sampler default:** `EngineV2`'s default sampler is now `CBv2DefaultSampler` (full pipeline: bias → penalties → temperature → top-k/p/min-p → keyed Gumbel-max); `CBv2GreedySampler` remains as the deterministic stub for scheduler tests.
- **Detokenizer (B§3, E):** `CBv2TextDetokenizerFactory` composes `DetokenizerV2` (UTF-8 holdback) + `StopHoldback` (stop-string holdback) behind `CBv2IncrementalDetokenizer`; a stop completed by the flush tail still truncates.
- **B§5 (rejection surface):** kept WS-B's shape — shutdown/queue-full throw `capacityExhausted`, degenerate requests get an immediate `.finished` stream. No contract change.
- **E§1 (`topLogprobs == 0` + logprobs=true):** kept WS-E's shape (`topLogprobs > 0` is the sole trigger); logprobs are not yet emitted in engine deltas — left for the provider-bridge pass (see "left for review" in the integration report).
- **E§3/E§4 (nil-seed, repetition window):** WS-E's choices stand as documented; no contract change.
- **F§1 (`newCacheV2` factory):** kept as the model-side injection point; `CBv2LayerCacheBank(caches:)` wraps its output as the engine's `CBv2LayerCacheProvider` (and `CBv2LayerCacheBank(layerKinds:attentionSoftcap:)` builds contiguous caches directly). GPT-OSS load-time sink priming (F§4) is preserved by routing cache construction through `newCacheV2`.
- **F§2 / C§5 (positionOffsets semantics):** documented in the contract — pre-update snapshot semantics; KV-shared layers own no rows, models must reuse the SOURCE layer's captured offsets.
- **G§1 (steppable-model protocol):** harness re-pointed at the real `CBv2SteppableModel`; the `CBv2HarnessSteppableModel` mirror is retired. `CBv2SteppableLanguageModelAdapter` bridges any `LanguageModel` (Gemma 4 / GPT-OSS v2 branches) into `CBv2SteppableModel`; `PagedLayerCache` gained the same legacy-`KVCache` trap conformance as `CBv2LayerCache` so it can travel through `[KVCache]` model plumbing.
- **G§2 (legacy compiled-decode divergence):** unchanged; out of CBv2 scope (owner: compiled-decode path). Parity gate behavior as documented in CONTRACT-ISSUES-G §2.
- **D§2 (per-request cacheSalt):** deferred — per-instance salt stands; per-tenant scoping is a provider-bridge concern (left for review).
